Test Matrix Using Trusted Data

Output contract tests

Assert exact column names, minimum row counts, latest baseline dates, and stable final filenames for both trusted CSVs.

NSW link discovery tests

Use saved current HTML fixtures to assert yearly and weekly links are classified by URL path and filename, not button class.

NSW DAT parser tests

Parse a tiny DAT fixture into long records and compare against a golden CSV derived from the known mapping.

NSW transform tests

Feed trusted ETL2 sample rows and assert the final wide schema matches data/nswgov_df.csv.

Rentboard parser tests

Use a small generated XLSX with header row 2 and expected columns to assert normalized output columns and date parsing.

Append behavior tests

Start from a trusted subset, add one synthetic newer period, then prove old rows are preserved and only new period rows are added.

Known Risks

Duplicate or corrected periods: newer annual NSW files may overlap weekly rows already captured. Use period keys and audit counts before final concat.
Source layout drift: both live sites have enough naming/class variation to require fixture tests around discovery.
Mixed historical typing: trusted CSVs contain old string-like values such as U in rent fields, so validation must preserve compatibility while checking new rows more strictly.
Large files: full CSV tests should use sampled fixtures; final audits can stream or chunk read the trusted CSVs.

Open Review Points

Raw/intermediate data location
Recommended: data/raw/{source} and data/interim/{source}, while final files stay at data/*.csv.
How much backward compatibility to keep
Recommended: keep etl1_pull/..., etl2_extract/..., and etl3_transform/... as wrappers for now, then retire them after a successful update.
Whether to revive etl4
Recommended: no. Treat etl4 as a separate project because it targets legacy listing-source joins, not the two trusted CSVs requested here.
